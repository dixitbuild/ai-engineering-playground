1.Question: When should I use which model in an agent?
Answer: For simple, cheap tasks, use a small model. For complex reasoning, long context, or multi-step tool use, use a more capable model. Start with reliability, then optimize for cost and latency.

Imagine your agent is a worker. If the job is simple and you want it done quickly and cheaply, give them a small tool. If the job is tricky, has many steps, or needs careful thinking, then give them the stronger tool. Start simple, then upgrade if accuracy, complex reasoning, long context, or tool use demands it. So, small model for quick, cheap tasks; bigger model for harder slower thinking tasks. Pick for reliability first, then cost. That's the core idea.

2. Question: How we can handle reliability
Answer: In practice, I handle reliability with several layers. 
First, choose a stable model and keep the temperature low, so outputs are more consistent. 
Second, constrain outputs with structured schemas so the agent returns predictable fields. 
Third, add retries with backoff for transient failures, and set timeouts and circuit breakers so problems fail fast instead of cascading.
Fourth, log inputs, outputs, latencies, and errors, and monitor for regressions. And finally, test fallbacks, such as a smaller model or a cached answer, 
so the system degrades gracefully, not catastrophically.

3. How we can reduce as possible as hallucination

Then validate outputs with simple rules. 
For instance, if a field must be a date, check the date format, if it must be a number, parse and bound it.

And finally, keep a human in the loop for high impact decisions until you've measured reliability in production.

4. Why do we use ChatPromptTemplate in LangChain?
We use ChatPromptTemplate in LangChain to structure and reuse prompts cleanly. It separates system instructions from user inputs using placeholders, making it easier to maintain as your agent grows. 
It doesn't make the model smarter or guarantee correctness; it just makes prompts cleaner, reusable, and easier to manage.

5. How do you handle max token limits when an LLM generates incomplete JSON?
When an LLM reaches its maximum output token limit before completing a JSON response, it may return incomplete JSON. This causes parsing errors because the parser expects a valid, complete JSON structure.
To handle this problem, I use the following approaches:
Set an appropriate token limit: Configure the maximum output tokens based on the expected response size.
Use structured outputs: Use the model's structured output or JSON schema feature when supported to enforce the required output structure.
Check the finish reason: Before parsing, check whether the model stopped because it reached the token limit. If the response was truncated, do not treat it as complete.
Reduce the output size: Shorten the prompt or request fewer items to reduce token consumption.
Split large tasks into batches: Generate large JSON outputs in smaller chunks instead of requesting everything in one response.
Handle parsing errors safely: Validate the response before parsing. If generation was truncated, retry with an appropriate token budget or process the remaining task separately.
Example: If an agent must generate 100 records but the output limit is insufficient, I can generate 20 records per batch, validate each JSON response, and combine the validated results.
Key takeaway: I prevent incomplete JSON by managing the token budget, using structured outputs, checking the finish reason, and implementing safe retry or batching logic. I never assume that a response is valid JSON simply because the model was instructed to return JSON.

6. What are the 5 types of agents in AI?
    1. Simple Reflex Agents
    How they work: They operate using direct condition-action (if-then) rules based only on the current percept, ignoring the history of the environment.
    Key characteristic: They have no memory and work best in fully observable, predictable environments.
    Example: A basic thermostat that turns the heat on or off depending solely on the current room temperature.
    2. Model-Based Reflex Agents
    How they work: They maintain an internal state or "world model" that tracks aspects of the environment that are currently unobservable.
    Key characteristic: They remember past states to understand how the world changes independently and how their own actions affect it.
    Example: A self-driving car tracking the position of nearby cars that are temporarily hidden behind a truck
    3. Goal-Based Agents
    How they work: They combine internal state information with explicit goals, evaluating future scenarios to choose actions that lead toward their target.
    Key characteristic: They involve multi-step planning and problem-solving rather than instant reactions.
    Example: A GPS navigation app calculating a route to a destination while actively avoiding road closures
    4. Utility-Based Agents
    How they work: They evaluate goals using a "utility function" that measures how desirable or optimal a specific outcome is.
    Key characteristic: They can balance competing trade-offs (such as speed, cost, safety, and risk) to maximize overall satisfaction or benefit.
    Example: A dynamic pricing algorithm that adjusts e-commerce prices by balancing profit margins against competitor rates and customer demand. 
    5. Learning Agents
    How they work: They are divided into a learning element, a performance element, a critic, and a problem generator.
    Key characteristic: They improve their performance over time through experience, adapting to changes in the environment via feedback loops.
    Example: An AI fraud-detection system that continuously updates its transaction rules as it encounters new types of cyber-attacks
